Databricks 从 DBRX 转向 Agent：战略收敛还是追逐 AI 热点？

日期：2026-07-17

Databricks 过去三年的 AI 路线看起来像一连串快速换挡：Dolly、13 亿美元收购 MosaicML、DBRX、Mosaic AI，再到 Agent Bricks 和 Omnigent。

最尖锐的解释是，Databricks 没能建立持续的通用模型业务，于是不断上移产品叙事，以保持自己在最新 AI 热点中的相关性。

这个 bear case 有真实基础，但最强版本说过头了。综合评分约为 6.5/10。

更准确的判断是：Databricks 已让通用自研 foundation model 从战略主角退场，但没有退出 AI training 或 serving；它正在把价值控制点移到模型之上的 data、context、evaluation、runtime 和 governance。

这既是对市场重心变化的追赶，也是符合 Databricks 既有资产结构的战略收敛。“追逐 relevance”可以解释发布节奏和品牌变化的一部分，但它是外部解释，不是可以从公开材料验证的管理层动机。

六个名称，六种不同对象

把 Dolly、MosaicML、DBRX、Mosaic AI、Agent Bricks 和 Omnigent 串成一条“模型产品失败史”，首先会犯分类错误。

名称 它是什么 是否为自研 foundation model 战略作用
Dolly 2.0 基于 EleutherAI Pythia-12B 微调的开放模型与数据集 否，不是从零预训练 展示低成本、可商用的开放 instruction tuning
MosaicML 被收购的训练平台、研究团队、MPT 模型和训练软件 团队具备从零训练能力 补齐大模型训练、系统优化和产品能力
DBRX Databricks/Mosaic 团队从零训练的 132B MoE 开放权重模型 是 证明训练、数据和 serving 栈能支撑大模型
Mosaic AI 训练、serving、vector search、gateway、agent 等产品的总品牌 否 统一包装 Databricks 的 AI 产品线
Agent Bricks 从自动评测和优化 builder 扩展出的企业 agent 平台 否 控制模型之上的 context、evaluation、runtime 和 governance
Omnigent 位于 Claude Code、Codex、Cursor、Pi 等 harness 之上的 meta-harness 否 统一不同 harness，并加入 policy、sandbox、协作和组合能力

因此，Dolly 不是 DBRX 的前代通用模型，Mosaic AI 也不是 Agent Bricks 的同类替代品。真正发生的变化是：通用 first-party model 的重要性下降，模型之上的 control plane 重要性上升。

从 Dolly 到 DBRX：真正退场的是什么

Dolly 本来就不是通用模型护城河

Dolly 2.0 的发布文明确说，它是基于 EleutherAI Pythia 的 12B 模型，并用新建的人类指令数据集微调：

“Dolly 2.0 is a 12B parameter language model based on the EleutherAI Pythia model family and fine-tuned exclusively on a new, high-quality human generated instruction following dataset.”

官方还主动限定了目标：

“As a technical and research artifact, we don't expect Dolly to be state-of-the-art in terms of effectiveness.”

Dolly 的意义是开放数据、商业许可和 instruction tuning 示范。它后来没有成为旗舰模型，不足以证明一次 foundation-model strategy failure。

MosaicML 收购确实押注过“企业自己训练模型”

收购协议将交易估值写为约 13 亿美元，包含留任安排，并给出清楚的战略承诺：

“Together, Databricks and MosaicML will enable any company to build, own and secure best-in-class generative AI models while maintaining control of their data.”

收购完成公告继续强调 bespoke LLM 的训练和部署，并表示 MosaicML 产品会继续直接销售。

这与 2026 年以第三方 frontier models、任意 harness 和企业 agent 为中心的叙事确实不同。收购 thesis 后来发生了变化，不能用品牌连续性掩盖这一点。

DBRX 是 first-party foundation model 的高点

DBRX 发布文显示，它不是一次简单微调：模型有 132B 总参数、36B active parameters，以 12T text/code tokens 预训练，使用 3,072 张 NVIDIA H100，主要构建过程约三个月，并开放 base 和 instruct weights。

官方当时写道：

“DBRX is a central pillar of our next generation of GenAI products.”

“This is also just the beginning of our work on DBRX, and you should expect much more to come.”

但仅 13 个月后，2025 年 4 月 release notes记录 DBRX Instruct 从 Foundation Model APIs 的按 token 服务中退役。到 2026-07-17，当前模型目录已包含多家供应商的模型，却没有 DBRX；现有公开材料中也未找到 DBRX 2 或通用后继模型。

这是 bear case 最硬的证据：DBRX 退出官方按 token 服务，而公开材料中未找到替代它的同系列新版本。它支持“通用 first-party model ambition 收缩”，但负面检索不能证明 Databricks 内部已停止所有通用模型研究。

Training 和 serving 没消失，只是商业形态变了

“DBRX 退场”不等于“Databricks 退出 AI infrastructure”。training 和 serving 都还在，只是不再围绕自有通用模型组织价值。

Training：从封装产品转向通用 GPU runtime

Foundation Model Fine-tuning 文档已标为 deprecated，并计划于 2026-08-14 移除，官方要求迁移到 AI Runtime。

与此同时，AI Runtime 发布文明确表示：

“AI Runtime contains all the technology used for large scale training of LLMs such as MPT and DBRX.”

AI Runtime 提供 serverless A10/H100、Composer、Hugging Face、Ray、PyTorch、MLflow 和 Unity Catalog。到文章日期，单节点 8x H100 为 Public Preview，多节点仍为 Private Preview；Model Training 产品页也仍宣传 fine-tuning 和从零训练 custom LLM。

所以变化不是训练能力消失，而是高度封装的 fine-tuning 入口退场，训练成为更通用的基础设施。公开可见的重点也从 DBRX 后继转向 small/domain models、RL、TAO 和 agent optimization。现有 AI Runtime 容量不能直接等同于 DBRX 当年的 3,072-H100 训练规模。

Serving：从自有模型 endpoint 转向多模型分发和治理

官方模型目录显示，Databricks 正托管 OpenAI、Anthropic、Google、Meta、Alibaba 等公司的模型，并将其置于 Databricks security perimeter 内。

2024 年，DBRX 同时证明 Databricks 的 training 和 serving 栈。2026 年，第三方 frontier models 提供 intelligence，Databricks 提供 endpoint、security、routing、budget、logging、evaluation 和 enterprise context。

这种平台模式不必押注单一模型赢家，却也依赖上游模型公司和底层云。model providers 与 cloud providers 可能拿走更高比例的价值和毛利。

MosaicML 收购复盘：模型家族没有延续，能力没有清空

认为 MosaicML 的原始故事被削弱，有四条直接依据：

  • 13 亿美元交易最初围绕“build, own and secure your own models”，现在的中心是“any model, any harness”。
  • MPT 没有发展成持续的一线通用模型家族。
  • 公开材料中未找到 DBRX 后继，它也已退出官方按 token 模型目录。
  • TechCrunch报道 Naveen Rao 于 2025 年 9 月离开 Databricks。

但“收购资产已被浪费”也不符合现有证据：

  • Hanlin Tang 的 2026 Summit 简介仍将这位 MosaicML 联合创始人列为 CTO - Neural Networks，并称其负责 Databricks AI products。
  • Agent Bricks 2025 和 AI Runtime 2026 的发布团队都包括 Hanlin Tang。
  • InfoWorld报道 Agent Bricks 使用了 MosaicML research division 开发的 TAO、synthetic data 和 Mosaic Agent 技术。
  • mosaicml/llm-foundry 与 mosaicml/composer 仍未归档，并在 2026 年保持更新。
  • DBRX 至少证明了收购团队能在 Databricks 上完成大规模预训练，相关经验进入 AI Runtime、评测和 agent learning。

公开资料不足以计算 MosaicML 团队的整体留存率。一位创始人离职和另一位创始人留任，都不能代表完整团队。

更合理的结论是：MosaicML 没有把 Databricks 变成持续发布通用模型的 frontier lab，但提供了训练、系统优化、评测和 agent learning 的技术组织。收购回报正从“模型家族”转化成“AI platform capability”；它是否值 13 亿美元，无法从公开收入拆分中验证。

Agent Bricks：从清晰差异点到大而全平台

2025 年的原始差异化

Agent Bricks 初始发布并不只是又一个 agent orchestration 产品。它的核心是 evaluation-to-optimization loop：

  1. 用户描述任务并连接数据。
  2. 系统生成 task-specific evaluation datasets 和 LLM judges。
  3. 系统搜索 prompt、model choice、fine-tuning、reward models 和 TAO 等方案。
  4. 用户在 cost-optimized 与 quality-optimized 结果之间选择。

InfoWorld 当时的评价是，许多竞品集中在 hosting 和 orchestration，而 Agent Bricks 试图自动化从评测到优化的完整链条。这是其最可信的原始差异化。

但 Databricks 所称“最高 10x lower cost”和客户准确率提升主要来自公司与客户案例，不是统一的独立测试。自动优化还依赖有效 benchmark 和 judge；如果任务成功无法被准确度量，系统只会更高效地优化一个不完整指标。

2026 年的全面扩张

Agent Bricks 2026 更新称：

“What began as an experiment in agent building has expanded into a comprehensive platform for developers to build agents with any model and any harness, access data anywhere, and confidently deploy and control.”

新范围包括 models、harnesses、Apps deployment、MCP、Genie Ontology、agent tools、Lakebase memory、document intelligence、Sandbox、Unity AI Gateway、traces、policies 和 Unity Catalog registry。

官方还披露 100k+ agents 和 1+ quadrillion tokens per year。这些是采用信号，但 agent 创建数不等于生产 agent 数，年化 token 也没有披露客户分布、收入或毛利。

覆盖面扩大可能提高产品 attach rate，却会稀释最初容易理解的差异点，并带来集成复杂度、产品重叠和“每一层都不够深”的风险。

Omnigent：有意思的 wedge，还不是护城河

Omnigent 发布文针对一个具体问题：不同 agent harness 各自持有 session、context、controls 和 interfaces，难以互换和组合。

Omnigent 在这些 harness 之上提供统一层，可组合 Claude Code、Codex、Cursor、Pi、自定义 agents 和 SDK agents，并支持一行配置切换 harness/model、stateful policies、cost controls、OS sandbox、network request interception、实时协作、共享 session，以及用 YAML 定义可迁移的 agent。

它不是 Agent Bricks 的同义词。Omnigent 是开源 meta-harness；Agent Bricks 是企业 agent 平台；托管 Omnigent 则是 Agent Bricks 的一个 harness 和 orchestration 入口。

成熟度必须降权看待：

  • 2026-06-13 发布时，开源版明确标为 alpha。
  • 托管版文档截至 2026-07-17 仍为 Beta，需要 workspace preview；Sandbox 仅在特定区域可用，custom policy functions 尚不支持。
  • GitHub repository核查时约有 7.4k stars、1.1k forks、1,584 commits，最新版本是 2026-07-10 的 v0.5.1。这证明开发活跃和开发者兴趣，不证明企业生产采用。

如果 harness 快速轮换，Omnigent 可以让 Databricks 持有 session、policy、identity、sandbox、collaboration 和 spend control，而不必拥有最强 harness。

但上游产品可以改变 API、授权和边界；common-denominator abstraction 可能损失各 harness 的独有能力；云厂商、LangChain、IDE 厂商和企业内部平台也能开发 adapters。Apache 2.0 许可有利于采用，同时降低了纯代码层的排他性。

当前最合理的定位是：Omnigent 是有技术品味、值得观察的 wedge，不是已经验证的 moat。

Gartner 2025 年预测，到 2027 年底超过 40% 的 agentic AI 项目将因成本上升、商业价值不清或风险控制不足而被取消。这个预测不证明 Agent Bricks 是 agent washing，但说明拥有一张完整 agent platform 清单本身没有多少战略信息量。

Databricks 真正不同的地方

Databricks 的优势真实存在，但主要来自已有平台组合，而不是 Agent Bricks 或 Omnigent 的单点算法。

  1. 数据邻近性。 tables、documents、features、permissions、lineage、traces 和 memory 可以留在同一数据平台，减少复制和重复治理。
  2. Unity Catalog 的统一资产模型。 agents、models、tools、MCP 和 data assets 可以进入同一 registry 和权限体系。
  3. MLflow 加自动优化。 task-specific benchmark、judges、模型与 prompt 搜索，可与 traces 和 lifecycle 管理结合。
  4. 模型与 harness 中立。 Databricks 不必保护自己的 frontier model，可以跨 OpenAI、Anthropic、Google、Meta 和开放模型做 routing 与成本优化。
  5. 跨云一致性。 相比单一 hyperscaler，Databricks 可在 AWS、Azure 和 GCP 上提供较一致的数据与 AI 控制层。

这些优势也有边界。Snowflake、BigQuery、Fabric 和 hyperscalers 都在主张数据邻近性；Unity Catalog 与 MLflow 的价值很大程度上来自客户已经在使用 Databricks；any model 同时意味着 Databricks 不控制 intelligence roadmap、上游价格或最优的 model-harness integration。

最准确的 moat 描述是：

installed data gravity + governance + workload integration + consumption distribution

而不是：

竞争对手无法复制的 agent algorithm 或 foundation model。

最强 bear evidence

  1. DBRX 的承诺与产品寿命存在明显落差。 central pillar 和 expect much more to come 之后，模型 13 个月即退出按 token 服务，且公开材料中未找到系列后继。退役是直接事实，后继缺失则是截至文章日期的负面检索结论。
  2. 资本与发布重点转向 agent layer。 Agent Bricks、Quotient AI、Unity AI Gateway、Sandbox、memory 和 Omnigent 集中出现，而不是 DBRX 2。资源优先级变化可以观察，但不能由此证明管理层动机。
  3. Agent Bricks 与大厂定位高度收敛。 多模型、多框架、deployment、identity、MCP、memory、observability、evaluation 和 governance 已被广泛覆盖。
  4. Omnigent 尚早，却迅速进入旗舰叙事。 alpha 开源版和 Beta 托管版的产品状态是事实；称其为过度营销则属于判断。
  5. 多模型中间层存在经济价值泄漏。 Databricks 不拥有主要 frontier model，也不控制底层云。CNBC 2026 年 6 月报道称其 AI products 年化收入达到 17 亿美元，但底层模型成本正在压低利润率；Ali Ghodsi 未披露当前 gross margin，只确认还会下降。

最强反驳

  1. 退出 DBRX endpoint 不等于退出 AI infrastructure。 AI Runtime、Model Training、Model Serving、Foundation Model APIs、Unity AI Gateway、MLflow 和 Agent Bricks 仍在扩张。
  2. Agent 方向与既有资产高度一致。 企业 agent 的难点正落在 data access、identity、context、evaluation、cost、security 和 production operations，这些正是 Databricks 的能力邻域。
  3. MosaicML 技术仍在新产品中发挥作用。 TAO、synthetic evaluations、fine-tuning、Composer、训练经验和关键技术领导者都延续到了新平台。
  4. 放弃通用模型竞赛可能是正确的资本配置。 与 OpenAI、Anthropic、Google、Meta 持续比拼通用模型需要巨额 compute，却未必形成企业分发优势。
  5. 已经出现采用与收入信号。 100k+ agents、年化 1+ quadrillion tokens 和 17 亿美元 AI products 年化收入至少说明这不是没有用户的概念展示；但采用规模和价值捕获质量必须分开评价。

评分没有达到 8-9 分，因为 training 和 serving 仍在，MosaicML 的技术连续性可见，既有 data/governance 基础不是竞争者靠一张 roadmap 就能复制，而且退出通用模型竞赛可能提高战略胜率。

评分也没有低到 3-4 分，因为 DBRX 的公开后继缺失是明显的不连续；Agent Bricks 从清晰的自动优化产品膨胀为总平台；Omnigent 在 alpha/Beta 阶段就进入旗舰故事；Databricks 还面临模型供应商与云厂商从上下游同时压缩价值的风险。

最终判断

最熊但仍准确的表述是：

Databricks 花 13 亿美元买到了成为 foundation-model company 的技术资格，却没有把这种资格延续成通用模型家族。随着 DBRX 退出官方 endpoint，它把 AI ambition 上移到 agent evaluation、context、governance 和 meta-harness；但这些层已经挤满 AWS、Microsoft、Google、Snowflake、LangChain、OpenAI 和 Anthropic，产品清单很难成为独占 moat。

最强反驳是：

Databricks 不需要赢得通用模型竞赛。企业 AI 的稀缺资源正在从 model weights 转向可信数据、业务语义、权限、评测、运行时和成本控制。Databricks 已经拥有这些资产，DBRX 的长期价值也可能更多是证明训练栈，而不是建立模型 franchise。

综合来看，这是一次真实、理性但不保证成功的战略收敛。追逐 relevance 是一种有证据支持但无法直接验证的解释，不能替代商业逻辑分析。Agent Bricks 和 Omnigent 的技术护城河弱于 Databricks 已有的 data、governance 与 workload 组合护城河；最终胜负取决于后者能否有效延伸为 enterprise AI control plane。

未来 6-18 个月的观察指标

  1. 是否出现 DBRX 后继或新的通用开放权重模型；若继续缺席，first-party foundation-model 退场判断会更强。
  2. AI Runtime 是否从单节点 8x H100 Public Preview 进入成熟多节点 GA，并披露大型客户训练规模。
  3. Agent Bricks 是否披露 production agents、付费客户、retention、独立收入和第三方质量/成本 benchmark，而不只是 agent/token 总量。
  4. Omnigent 是否从 alpha/Beta 进入 GA，保持多 harness feature parity，并出现 Databricks 之外的生产采用。
  5. Unity AI Gateway、Agent Bricks 和第三方 model serving 的 gross margin，尤其是模型与云成本是否稀释 AI 增长的经济性。
  6. Microsoft、AWS、Google 和 Snowflake 是否复制 Agent Bricks 的自动 benchmark 和 optimization 优势。
  7. MosaicML 原团队是否继续领导核心 AI 产品，以及 LLM Foundry、Composer、TAO、KARL 等技术能否持续转化为差异化产品。

Databricks From DBRX to Agents: Strategic Focus or a Bid to Stay Relevant?

Date: July 17, 2026

Databricks' AI strategy has changed gears several times in three years: Dolly, the $1.3 billion acquisition of MosaicML, DBRX, Mosaic AI, and now Agent Bricks and Omnigent.

The sharpest bearish interpretation is that Databricks failed to establish a durable general-purpose model business and has kept moving its product narrative up the stack to remain relevant to the latest AI trend.

That case has a real factual basis, but its strongest version goes too far. Overall, it deserves roughly 6.5/10.

The more precise conclusion is that first-party, general-purpose foundation models have receded from the center of Databricks' strategy. The company has not abandoned AI training or serving; it is moving the point of control above the model, toward data, context, evaluation, runtime, and governance.

This is partly a response to where the market is moving and partly a rational focus on assets Databricks already owns. “Staying relevant” may explain some of the branding and release cadence, but it is an interpretation, not a management motive that public evidence can establish.

Six Names, Six Different Things

Treating Dolly, MosaicML, DBRX, Mosaic AI, Agent Bricks, and Omnigent as a single sequence of failed model products begins with a category error.

Dolly was not an earlier version of DBRX, and Mosaic AI is not a product that Agent Bricks replaced one-for-one. The actual strategic transition is simpler: first-party general models matter less, while the control plane above models matters more.

From Dolly to DBRX: What Actually Receded

Dolly Was Never a General-Model Moat

The Dolly 2.0 announcement describes a 12B model based on EleutherAI's Pythia family and fine-tuned on a newly created human instruction dataset:

“Dolly 2.0 is a 12B parameter language model based on the EleutherAI Pythia model family and fine-tuned exclusively on a new, high-quality human generated instruction following dataset.”

Databricks also set expectations explicitly:

“As a technical and research artifact, we don't expect Dolly to be state-of-the-art in terms of effectiveness.”

Dolly demonstrated open data, commercial licensing, and instruction tuning. Its later absence from the flagship model lineup is not evidence that a serious foundation-model strategy failed; that was never the product's intended role.

MosaicML Did Represent a Bet on Enterprise-Owned Models

The acquisition agreement valued the transaction at about $1.3 billion, including retention packages, and made the strategic promise explicit:

“Together, Databricks and MosaicML will enable any company to build, own and secure best-in-class generative AI models while maintaining control of their data.”

The closing announcement continued to emphasize training and deploying bespoke LLMs, while saying MosaicML products would remain available directly.

That position is plainly different from the 2026 emphasis on third-party frontier models, any harness, and enterprise agents. The acquisition thesis evolved; brand continuity should not obscure that change.

DBRX Was the High-Water Mark for First-Party Models

The DBRX launch was not a fine-tuning exercise. DBRX had 132 billion total parameters and 36 billion active parameters, was pretrained on 12 trillion text and code tokens, used 3,072 NVIDIA H100s over a core build period of roughly three months, and shipped with open base and instruct weights.

Databricks wrote at the time:

“DBRX is a central pillar of our next generation of GenAI products.”

“This is also just the beginning of our work on DBRX, and you should expect much more to come.”

Only 13 months later, the April 2025 release notes recorded the retirement of DBRX Instruct from Foundation Model APIs pay-per-token. As of July 17, 2026, the supported-model catalog included models from many outside providers but no DBRX. Available public materials also yielded no DBRX 2 or general-purpose successor.

This is the strongest evidence for the bear case. DBRX left the official pay-per-token service, and no same-family replacement was found in public materials. That supports a retreat in first-party general-model ambition, but a negative search does not prove Databricks has ended all internal research on general models.

Training and Serving Remain, in Different Commercial Forms

DBRX's retreat is not the same as Databricks leaving AI infrastructure. Both training and serving remain active, but the value proposition is no longer organized around a first-party general model.

Training: From a Packaged Product to a General GPU Runtime

The Foundation Model Fine-tuning documentation marks the product deprecated and scheduled for removal on August 14, 2026, directing customers to AI Runtime.

At the same time, the AI Runtime announcement says:

“AI Runtime contains all the technology used for large scale training of LLMs such as MPT and DBRX.”

AI Runtime includes serverless A10 and H100 GPUs, Composer, Hugging Face, Ray, PyTorch, MLflow, and Unity Catalog. As of the article date, a single node with eight H100s was in Public Preview and multi-node support remained in Private Preview. The Model Training product page still advertises fine-tuning and training custom LLMs from scratch.

Training capability has not vanished. A highly packaged fine-tuning entry point is giving way to broader infrastructure, while public emphasis has shifted from a DBRX successor to small and domain models, reinforcement learning, TAO, and agent optimization. Current AI Runtime capacity should not be equated with DBRX's 3,072-H100 training run.

Serving: From a First-Party Endpoint to Multi-Model Distribution

The current model catalog shows Databricks hosting models from OpenAI, Anthropic, Google, Meta, Alibaba, and others within the Databricks security perimeter.

In 2024, DBRX validated both the training and serving stack. In 2026, outside frontier models supply the intelligence, while Databricks supplies endpoints, security, routing, budgets, logging, evaluation, and enterprise context.

This platform position avoids betting on one model winner. It also makes Databricks dependent on upstream model companies and underlying clouds, which may capture more of the value and margin.

Revisiting MosaicML: The Model Family Faded, the Capabilities Did Not

Four facts support the view that MosaicML's original story lost value:

  • The $1.3 billion transaction was sold around building, owning, and securing models; the current center of gravity is “any model, any harness.”
  • MPT did not develop into a sustained top-tier family of general-purpose models.
  • No DBRX successor was identified in public materials, and DBRX left the official pay-per-token catalog.
  • TechCrunch reported that Naveen Rao left Databricks in September 2025.

The claim that the acquired assets were simply wasted is also inconsistent with the evidence:

  • Hanlin Tang's 2026 Summit profile lists the MosaicML co-founder as CTO - Neural Networks and says he is responsible for Databricks' AI products.
  • Tang was part of the launch teams for both Agent Bricks in 2025 and AI Runtime in 2026.
  • InfoWorld reported that Agent Bricks uses TAO, synthetic data, and Mosaic Agent technology developed by the MosaicML research division.
  • mosaicml/llm-foundry and mosaicml/composer remain unarchived and continued to receive updates in 2026.
  • DBRX proved that the acquired team could complete large-scale pretraining on Databricks, and that experience carries into AI Runtime, evaluation, and agent learning.

Public information is not sufficient to calculate retention across the whole MosaicML team. One founder's departure and another's continued leadership cannot stand in for a complete roster.

The fair retrospective is that MosaicML did not turn Databricks into a frontier lab that releases a continuing family of general models. It did provide an organization capable of model training, systems optimization, evaluation, and agent learning. The return is shifting from a “model family” to “AI platform capability.” Public revenue disclosure is not granular enough to determine whether that return justified $1.3 billion.

Agent Bricks: From a Clear Wedge to a Broad Platform

The Original 2025 Differentiation

The initial Agent Bricks launch was more specific than a generic orchestration announcement. Its core was an evaluation-to-optimization loop:

  1. A user describes a task and connects data.
  2. The system creates task-specific evaluation datasets and LLM judges.
  3. It searches across prompts, model choice, fine-tuning, reward models, TAO, and other methods.
  4. The user chooses between cost-optimized and quality-optimized results.

InfoWorld's contemporaneous assessment was that many competing products concentrated on hosting and orchestration, while Agent Bricks automated more of the evaluation-to-optimization lifecycle. That was the product's most credible original differentiation.

There were important limits. Claims such as “up to 10x lower cost” and customer accuracy gains came mainly from Databricks and customer examples rather than standardized independent testing. Automated optimization also depends on a sound benchmark and judge. If task success is poorly specified, the system may simply optimize an incomplete metric more efficiently.

The 2026 Expansion

The 2026 Agent Bricks update says:

“What began as an experiment in agent building has expanded into a comprehensive platform for developers to build agents with any model and any harness, access data anywhere, and confidently deploy and control.”

The expanded scope includes models, harnesses, Apps deployment, MCP, Genie Ontology, agent tools, Lakebase memory, document intelligence, Sandbox, Unity AI Gateway, traces, policies, and a Unity Catalog registry.

Databricks also reported 100k+ agents and 1+ quadrillion tokens per year. Those are adoption signals, but agents created are not the same as agents in production, and an annualized token count says little about customer concentration, revenue, or margin.

Broader coverage may raise attach rates. It also weakens the original, easy-to-explain wedge and introduces integration complexity, product overlap, and the risk of being shallow at every layer.

Omnigent: An Interesting Wedge, Not Yet a Moat

The Omnigent announcement starts from a concrete problem: agent harnesses keep their own sessions, context, controls, and interfaces, making them difficult to combine or replace.

Omnigent adds a common layer over Claude Code, Codex, Cursor, Pi, custom agents, and SDK agents. It offers one-line harness and model switching, stateful policies, cost controls, OS sandboxing, network request interception, real-time collaboration, shared sessions, and portable agent definitions in YAML.

Omnigent is not another name for Agent Bricks. Omnigent is an open-source meta-harness; Agent Bricks is Databricks' enterprise agent platform; managed Omnigent is one harness and orchestration entry point inside Agent Bricks.

Its maturity needs to be discounted:

  • The open-source release was explicitly labeled alpha on June 13, 2026.
  • As of July 17, 2026, the managed documentation still labeled it Beta and required a workspace preview. Sandbox availability was limited by region, and custom policy functions were unsupported.
  • The GitHub repository had roughly 7.4k stars, 1.1k forks, and 1,584 commits when checked, with v0.5.1 released on July 10, 2026. That demonstrates active development and developer interest, not enterprise production adoption.

If harnesses turn over quickly, Omnigent could let Databricks retain control of sessions, policy, identity, sandboxing, collaboration, and spending without owning the best harness.

The risks are equally clear. Upstream products can change APIs, licensing, and boundaries. A common-denominator abstraction may hide each harness's distinctive capabilities. Cloud vendors, LangChain, IDE companies, and internal enterprise platforms can also build adapters. Apache 2.0 licensing helps adoption while reducing exclusivity at the code layer.

The right description today is: Omnigent is a technically thoughtful wedge worth watching, not a validated moat.

The overlap is visible in first-party documentation. AWS AgentCore emphasizes “Any framework. Any model.” Microsoft Foundry Agent Service supports multiple SDKs and an agent optimizer. Snowflake Cortex Agents combines governed data, a code sandbox, MCP, threads, monitoring, and evaluations.

“Any model, any harness, governed production agents” is rapidly becoming table stakes rather than a Databricks-exclusive position.

Gartner predicted in 2025 that more than 40% of agentic AI projects would be canceled by the end of 2027 because of rising costs, unclear business value, or inadequate risk controls. This does not establish that Agent Bricks is agent washing; it does show that possessing a complete agent-platform checklist conveys little strategic information by itself.

What Actually Makes Databricks Different

Databricks has real advantages, but they come mainly from the combination of its existing platform assets, not from an exclusive Agent Bricks or Omnigent algorithm.

  1. Data proximity. Tables, documents, features, permissions, lineage, traces, and memory can remain in one data platform, reducing copying and duplicate governance.
  2. Unity Catalog's shared asset model. Agents, models, tools, MCP endpoints, and data assets can use one registry and permission system.
  3. MLflow plus automated optimization. Task-specific benchmarks and judges, model and prompt search, traces, and lifecycle management can be connected in one system.
  4. Model and harness neutrality. Databricks has no frontier model to protect and can route and optimize cost across OpenAI, Anthropic, Google, Meta, and open models.
  5. Cross-cloud consistency. Compared with a single hyperscaler, Databricks can present a more consistent data and AI control layer across AWS, Azure, and GCP.

These advantages have limits. Snowflake, BigQuery, Fabric, and the hyperscalers all claim data proximity. Unity Catalog and MLflow are most valuable where a customer already uses Databricks. “Any model” also means Databricks does not control the intelligence roadmap, upstream pricing, or the best model-harness integration.

The most accurate description of its moat is:

installed data gravity + governance + workload integration + consumption distribution

Not:

an agent algorithm or foundation model that competitors cannot reproduce.

The Strongest Bear Evidence

  1. DBRX's promise and product life diverged sharply. After describing DBRX as a central pillar and saying “expect much more to come,” Databricks retired it from pay-per-token service 13 months later. No family successor was identified in public materials. The retirement is a direct fact; the missing successor is a negative-search conclusion as of the article date.
  2. Capital and releases moved toward the agent layer. Agent Bricks, Quotient AI, Unity AI Gateway, Sandbox, memory, and Omnigent arrived instead of DBRX 2. The priority change is observable; management intent is not.
  3. Agent Bricks converged with large-platform positioning. Multi-model and multi-framework support, deployment, identity, MCP, memory, observability, evaluation, and governance are broadly available.
  4. Omnigent entered the flagship narrative while still early. Its alpha open-source and Beta managed status are facts. Calling the positioning excessive is an interpretation.
  5. A multi-model middle layer leaks economic value. Databricks owns neither the leading frontier models nor the underlying cloud. CNBC reported in June 2026 that Databricks' AI products had reached $1.7 billion in annualized revenue, while underlying model costs were pressuring margins. Ali Ghodsi declined to disclose current gross margin but confirmed it would fall further.

The Strongest Counterarguments

  1. Retiring a DBRX endpoint is not an exit from AI infrastructure. AI Runtime, Model Training, Model Serving, Foundation Model APIs, Unity AI Gateway, MLflow, and Agent Bricks are still expanding.
  2. The agent direction fits Databricks' installed assets. Enterprise agents are constrained by data access, identity, context, evaluation, cost, security, and production operations, all adjacent to Databricks' strengths.
  3. MosaicML technology remains active in newer products. TAO, synthetic evaluations, fine-tuning, Composer, training experience, and key technical leadership carried into the new platform.
  4. Leaving the general-model race may be sound capital allocation. Competing indefinitely with OpenAI, Anthropic, Google, and Meta requires enormous compute spending without guaranteeing enterprise distribution.
  5. There are adoption and revenue signals. 100k+ agents, annualized volume above 1 quadrillion tokens, and $1.7 billion in annualized AI-product revenue indicate more than a userless concept demo. Adoption scale and quality of value capture still need to be evaluated separately.

The score is not 8 or 9 because training and serving remain active, MosaicML's technical continuity is visible, the installed data and governance base cannot be copied with a product roadmap, and leaving the general-model race may improve Databricks' odds.

It is not 3 or 4 because the absence of an identified public DBRX successor is a clear discontinuity; Agent Bricks expanded from focused optimization into an umbrella platform; Omnigent entered the flagship story in alpha and Beta; and model and cloud providers can compress Databricks' value from both sides.

Final Judgment

The most bearish formulation that remains accurate is:

Databricks paid $1.3 billion to acquire the technical capability to become a foundation-model company, but did not turn that capability into a continuing family of general-purpose models. As DBRX left the official endpoint, Databricks moved its AI ambition up to agent evaluation, context, governance, and the meta-harness layer. Those layers are already crowded with AWS, Microsoft, Google, Snowflake, LangChain, OpenAI, and Anthropic, making a feature checklist a weak basis for an exclusive moat.

The strongest rebuttal is:

Databricks does not need to win the general-model race. Scarcity in enterprise AI is moving from model weights toward trusted data, business semantics, permissions, evaluation, runtime, and cost control. Databricks already owns those assets, and DBRX's durable purpose may have been to validate the training stack rather than establish a model franchise.

On balance, this is a real and rational strategic focus, with no guarantee of success. Staying relevant is a plausible but unprovable interpretation, not a substitute for analyzing the business logic. The technical moat in Agent Bricks and Omnigent is weaker than Databricks' existing combination of data, governance, and workloads. The outcome depends on whether that existing moat can be extended into the enterprise AI control plane.

What to Watch Over the Next 6-18 Months

  1. Whether a DBRX successor or a new general-purpose open-weight model appears. Continued absence would strengthen the conclusion that first-party foundation models have receded.
  2. Whether AI Runtime progresses from a single-node, eight-H100 Public Preview to mature multi-node GA, with disclosure of large customer training runs.
  3. Whether Agent Bricks reports production agents, paying customers, retention, standalone revenue, and third-party quality and cost benchmarks rather than only agent and token totals.
  4. Whether Omnigent reaches GA, maintains feature parity across harnesses, and gains production adoption outside Databricks.
  5. Gross margin for Unity AI Gateway, Agent Bricks, and third-party model serving, especially whether model and cloud costs dilute the economics of AI growth.
  6. Whether Microsoft, AWS, Google, and Snowflake reproduce Agent Bricks' automated benchmark and optimization advantage.
  7. Whether the former MosaicML team continues to lead core AI products, and whether LLM Foundry, Composer, TAO, KARL, and related technology keep producing differentiated products.
